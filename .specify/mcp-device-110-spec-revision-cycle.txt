#### B4. Avoid premature process architecture complexity

The current spec strongly commits to server-side consumer IDs + destructive consume cursors + generations.

Re-evaluate this choice.

Prefer the simpler model unless concrete requirements disprove it:
- process output is an append-only logical byte stream
- read(session, absoluteOffset, maxBytes) is idempotent
- response returns nextOffset and oldestAvailableOffset
- observers/tail are views over offsets
- spill/retention preserve absolute positions
- an expired offset returns explicit OFFSET_EXPIRED / gap metadata
- optional acknowledgement may exist only as a GC watermark, not as delivery semantics

Do not mandate this alternative blindly either. Compare both models against:
- multiple readers
- retry after lost response
- memory reclamation
- completed replay compatibility
- observer semantics
- transport reconnect
- implementation complexity

Choose the simpler design that satisfies actual requirements and document the rationale/alternatives.
