# v12 complete state backup and legacy migration

Status: implemented and tested on Windows Node 22.22.2 and WSL Ubuntu Node 22.21.0, including all seven backup/migration cases in the final 77-case runtime suites. No real home, G8, production or backup runtime was read or modified for fixtures.

## Public platform APIs

All functions are Promise APIs exported from src/platform/state-backup.ts:

- planStateBackup({sourceRoot,backupRoot}) inspects an explicit stopped root and returns a hash inventory. It creates no destination or lease.
- createStateBackup({sourceRoot,backupRoot}) acquires the same server-runtime.lock lease as the server, copies every state file to a sibling staging directory, verifies source and destination hashes, then atomically publishes a new backup directory.
- verifyStateBackup({backupRoot}) verifies the manifest digest and exact file tree. Unexpected files, changed contents and invalid relative paths fail.
- restoreStateBackup({backupRoot,targetRoot}) verifies the full backup, restores to staging, verifies again, and publishes only into an absent target root. Existing targets are never replaced.
- planLegacyMigration({deviceRoot,gatewayRoot,targetRoot,backupRoot,dryRun?}) defaults dryRun to true and records every file mapping. It requires gateway.sqlite in the explicitly selected legacy Gateway root. No table conversion is needed: the imported Gateway factory uses its existing database schema/migrations.
- applyLegacyMigration({plan}) checks the unchanged plan and source fingerprints, locks both stopped sources, backs each up completely under backupRoot/device and backupRoot/gateway, then assembles and verifies a fresh unified runtime. If target assembly fails after backup, the verified backups remain available. Rollback means restoring the relevant prior backup into another empty root and switching the runtime explicitly; no live root is overwritten.

## State preservation and boundaries

The complete root includes Device identity/configuration, gateway.sqlite with accounts, sessions, invites, OAuth and pairings, the knowledge reference key, plugin registry, plugin private SQLite databases, managed evidence, audit files and unknown plugin files. The inventory is generic and does not inspect Palace internals or print secret contents. Only server-runtime.lock and plugins/registry.lock are excluded as process coordination metadata.

The canonical unified root is the explicit server --runtime-dir. The Gateway database maps to root/gateway.sqlite and existing Device state files keep their relative paths. Any file collision, including a case-insensitive portable collision, rejects planning; no identity or configuration wins silently. Secrets outside the selected roots are outside the snapshot, including external TOML and operating-system credential stores.

A live server lease or a live Device runtime IPC owner blocks backup. An existing Device runtime-control.json whose owner cannot be proved stopped also blocks it. Plugin registry activity blocks it. A nested server-runtime.lock, runtime-control.json or plugins/registry.lock rejects an ancestor-root snapshot with NESTED_RUNTIME_REQUIRES_SEPARATE_STOPPED_BACKUP, even for a claimed stale PID; all nested runtimes must be explicitly stopped and their ownership resolved first. A fully stopped nested runtime with no coordination marker is retained as ordinary state. Nonempty SQLite WAL or rollback journal files require stop/checkpoint before backup. This deliberately avoids copying a potentially inconsistent live database. Legacy processes that do not implement the shared server lease must already be stopped by the operator. Source rehashing before publish catches changes during copying.

Symlinks/junctions, nonregular files, traversal, overlapping source/destination trees and unmanifested payloads are rejected. Per-file SHA-256 and a manifest digest detect corruption; these hashes are integrity checks, not an external signature. File modes are retained as metadata and restored where the filesystem supports them; portable content fingerprints do not depend on Windows versus POSIX mode emulation.
